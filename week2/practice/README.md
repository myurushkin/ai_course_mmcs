# Практика недели 2: одиннадцать задач на OpenAI Agents SDK

Агенты над настоящими данными Ростова: 8860 мест из OpenStreetMap, из них 922 пункта выдачи заказов. Лекция показывает механику — как модель научили звать инструменты, что гарантирует схема, почему описание инструмента это интерфейс. Практика заставляет это сделать руками.

## Как устроено занятие

Задачи независимы: застрял на одной — переходишь к следующей, ничего не ломается. Зачёт — шесть из десяти; нулевая разминочная не в счёт. Материала на два часа при доступных ста минутах, и это намеренно: незачтённое доделывается дома.

| № | Задача | О чём |
|---|---|---|
| 0 | Разминка без фреймворка | вызов инструмента — участок ответа модели, а не действие |
| 1 | Первый агент | инструмент без описания не зовут, и никто об этом не предупредит |
| 2 | Цепочка | между инструментами доходит только текст результата |
| 3 | Запрос объектом | схема со списком значений против свободной строки |
| 4 | Описание решает | выбор инструмента измеряется числом, а не ощущением |
| 5 | Что нельзя выбрасывать | память диалога и цена её обрезки |
| 6 | Предохранитель и цена | круг в цикле лечится лимитом, а не промптом |
| 7 | Форма, при которой нельзя соврать | валидация отсекает часть вранья, но не всё |
| 8 | Гардрейл | посторонний запрос отсекается до того, как за него заплатят |
| 9 | Триаж | передача между агентами решается инструкцией, а не описаниями |
| 10 | Три адреса | отчёт агента сверяется с базой, и это единственный способ ему верить |

**Ячейки трёх видов**, вид подписан в первой строке: `# ДАНО` — готовый код, `# ЗАДАЧА N` — две-пять строк студента, `# ПРОВЕРКА` — что именно сошлось и что нет.

**Заготовки выглядят одинаково:** то, что нужно заполнить, стоит в коде как `"..."` с комментарием рядом; там, где нужен кусок кода, комментарий стоит перед ним и говорит, что этот кусок должен делать.

## Что нужно до начала

**Ключ к сервису с моделью** — от самой OpenAI или от посредника: сервис выбирается первой строкой во второй ячейке (`SERVICE = "openai"` или `"aitunnel"`). Ключ вводится в поле, а не в код, поэтому в сохранённый файл не попадает. Все задачи — порядка сорока пяти запросов на коротких промптах, то есть единицы рублей на недорогой модели.

**Имитации модели в практике нет.** Без ключа ноутбук честно останавливается: студент работает с настоящей моделью и видит её настоящие промахи.

**Три настройки SDK** разобраны в ноутбуке отдельно: фреймворк по умолчанию идёт в Responses API, в трассировку OpenAI и на свою модель — с ключом посредника не подходит ни одно из трёх, и предупреждения не будет. И ещё одно: `Runner.run_sync` в ноутбуке не работает вовсе, потому что цикл событий уже запущен; везде `await Runner.run(...)`.

## Что лежит в папке

| Файл | Зачем |
|---|---|
| `week02_agents.ipynb` | Ноутбук студента: одиннадцать задач с проверками |
| `sdk_tasks.py` | Данные, готовые инструменты над базой и проверки задач |
| `data/rostov_poi.json` | Снимок OpenStreetMap по Ростову, лицензия ODbL |
| `make_poi_dataset.py` | Сборка `poi.sqlite` из снимка |
| `img/` | Заставка и схемы |
| `requirements.txt` | Зависимости: `openai-agents`, `openai`, `pydantic` |

База `poi.sqlite` собирается из снимка одной командой — `python make_poi_dataset.py`; в публичный репозиторий она кладётся уже собранной, чтобы ноутбук в Colab заводился сразу.
