# Задание 1 (сдача через две недели, к 6 октября)

Продолжение практики, выполняется индивидуально на том же репозитории.

**Что нужно сделать.**

1. Довести до рабочего состояния три-пять инструментов и цикл без фреймворка: лимит шагов, ошибки как наблюдения, журнал в JSONL, счётчики токенов из `usage`. Репозиторий должен запускаться локально, а не только в Colab: это и есть проверка окружения первой недели.
2. Прогнать десять задач по три раза: `uv run python check.py --n 3`. В отчёт — pass@1 и pass^3, средние токены и стоимость задачи, число шагов.
3. **A/B описаний.** Два варианта описаний одних и тех же инструментов: «короткие» (одна фраза) и «полные» (что делает, когда использовать, когда не использовать, единицы, пример). По три прогона на вариант. Метрика — доля задач, где выбран верный инструмент и аргументы; интервал Вильсона. Ответить числом: окупились ли лишние токены описаний.
4. **Разбор ошибок.** Три неудачные траектории из журнала с классификацией: не тот инструмент, не те аргументы, ошибка среды, зацикливание, ложное «готово».
5. Отчёт на одну-две страницы в репозитории: таблица метрик, вывод по A/B, три разбора ошибок.

**Что сдаётся.** Ссылка на репозиторий с инструментами, циклом, папкой `runs/` и отчётом. Код должен запускаться по README на чистой машине одной командой.

**Рубрика (100).** Схемы и описания инструментов — 30. Цикл, лимиты и ошибки как наблюдения — 30. Метрики и A/B посчитаны верно — 25. Отчёт и разбор ошибок — 15.

**Типичные ошибки прошлых лет** (проговорить на паре):

- Инструмент бросает исключение — цикл падает вместо того, чтобы дать модели шанс исправиться.
- В ответ инструмента кладётся весь результат запроса: контекст и стоимость растут, качество падает.
- Нет лимита шагов: одна ошибка в фильтре превращается в бесконечный цикл и счёт на API.
- Метрики считаются по одному прогону, а вывод делается уверенный.
- Описание инструмента написано для человека, а не для модели: нет единиц, нет границ применимости.
